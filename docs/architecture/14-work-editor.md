# 模组详情与编辑

作品列表的「详情」「更新」「提交审核」进入同一个详情页, 使用已有 Panel、Button、Dialog、PageHeader、Tag 及 `--g-*` 主题令牌。基本信息、资源定价、详情与攻略、资源文件、图片与视频、更新与上架分为六个页签; 开启 PC 同步后显示 PC 配置。

## 分区编辑模式（2026-10-16）

已有作品进入详情时每个分区默认只读。分区右上角“更新”只打开本地编辑开关, 不请求保存或上传; 解锁后按钮变为“保存此分区”。顶部“保存”提交已解锁分区中的修改, 保存成功后相应分区恢复只读, 平台拒绝则保留草稿与编辑状态。关联 PC 开关和配置沿用成对保存逻辑。审核中、状态不允许编辑、请求处理中及写结果未知时不能解锁。

基础表单、价格、资源、富文本和 PC 分区使用同一 `EditorSection`; 图片、推广图和视频各有独立开关, 更新纪要与弱下架也独立控制。原生控件使用禁用 fieldset, 富文本显式关闭 contentEditable, 字段变更与上传函数再检查对应分区开关。新建作品直接可填写。

未保存草稿仍按账号/作品在内存中恢复, 但重新进入时编辑开关不恢复, 必须再次点对应分区更新。锁定分区的恢复草稿不会被普通顶部保存隐式提交; 尚有此类草稿时需先解锁处理才能提审。刷新得到新快照时重建编辑视图, 避免快速响应跳过 loading 渲染而继续使用旧平台状态。

操作记录: 抽出统一分区容器 → 增加本地编辑开关与保存成功重锁 → 接入媒体/富文本/上传开关 → 修正刷新快照更新 → 扩展隔离 UI 回归与项目文档。回归覆盖默认只读、更新不写入、分区独立、分区和顶部保存、失败保留、恢复草稿、新建直接填写及审核只读。所有验证使用本地模拟接口, 未操作真实作品。

## 接口与数据边界

协议参考 [MCDevManager d7ecc75](https://github.com/BitterLemonn/MCDevManager/tree/d7ecc75dac449addd0782870b85fc25fc1447bee), 按接口行为重新实现, 不引入其 Kotlin 源码。

| RPC | 平台请求 | 用途 |
|---|---|---|
| `works.page` | GET `/items/categories/pe/?start=…&span=9` | 作品管理按页加载, 使用响应 `count` 计算总页数 |
| `works.create` | POST `/items/categories/pe/upload` | 新建 PE 作品, 独立创建 DTO, `is_check_apply=false` |
| `works.editor` | GET `/items/categories/pe/{id}` | 编辑字段、状态、模组码、版本、已有攻略 |
| `works.options` | GET `/items/mc_consts/`, `/item-tag/` | 分类、推荐标签、API 版本、图片位尺寸及版本、PC 选项 |
| `works.save` | GET 详情后 POST `/items/categories/pe/{id}/update` | 合并本次字段变更, `is_check_apply=false` |
| `works.submitReview` | GET 详情后 PUT `/items/categories/pe/{id}/apply_review` | 独立提审, 显式用户确认后调用 |
| `works.upload` | GET `/filepicker/file_token`, token 指定的 FP 地址 | 原生文件选择、校验、流式上传 |

主进程核对调用窗口、当前账号和参数。目前写接口尚未暴露给 MCP；2026-10-16 已确认把创建、更新、提审纳入 MCP 接入范围，设计见 [13 能力层与 MCP 接入](13-mcp.md) 的作品编辑章节。渲染层不能传入本地路径; 当前上传仅使用原生选择器的结果, Cookie 不发送给文件上传服务。FP 地址只允许已确认的 HTTPS 域名, 拒绝重定向。

保存只接受已声明的编辑字段, 携带对应字段的基线。发送前重新获取详情, 已编辑字段若被其他客户端改动则拒绝覆盖; 未编辑的字段从最新详情保留。更新 DTO 过滤响应专用字段, 保留旧资源元数据、攻略、折扣等。已有图片 URL 与新文件签名回执分别保留正确的线上结构。64 位关联 ID 不经过 JavaScript Number 舍入。

该并发检查不是原子条件更新: 参考接口没有 revision/If-Match 协议, 仍存在读取与写入之间的短暂竞态窗口。

### 保存参数修复与真实验证（2026-10-16）

详情 GET 的返回字段不完整, 不能直接作为更新 DTO。保存适配器先建立独立的更新协议默认值, 再覆盖最新详情及用户改动; 补齐缺失的数组、数字、布尔值和文本字段, 处理 DLC 子字段的 null、空字符串哨兵、空授权证明及数字布尔值。保留资源、图片、视频等已有元数据, 不回传 `intercept_fields` 等响应专用字段。

用户明确授权使用截图中的测试作品 `4686664860310207622` 验证。本次通过运行中应用的 `works.save` 保存名称“猫咖啡测试专用”→“猫咖啡测试专用123”, 返回成功后再次调用 `works.editor` 核对: 名称已更新, 平台资源版本由 3.4 自动升至 3.5, 状态仍为 init; 编辑字段对比仅 `item_name` 变化。未提审, 未操作其他作品。此授权不扩大到其他作品或其他发布操作。

操作记录: 只读核对测试作品及协议 → 补齐更新默认值和空值转换 → 新增稀疏详情回归 → 52 项作品测试、全仓类型检查、构建和变更文件 Biome 通过 → 在指定测试作品执行一次名称保存并重新读取确认。UI 的默认只读、更新后编辑和保存后锁定流程保持不变。

保存成功后仅更新已保存字段, 其他分区草稿继续保留。草稿在本进程内按账号与作品隔离, 离开路由后可恢复, 不落磁盘。放弃修改有明确确认。超时或无法确认写结果时要求刷新核对, 不自动重发。保存与提审分别报告结果, `need_check_apply` 需要额外平台确认时不会显示提交成功。

富文本采用元素、属性、样式及 URL 白名单。远程图片通过既有 `glaze-image` 代理显示, 保存时恢复原 URL。裁剪预览使用主进程返回的 PNG 缩略图生成临时 Blob URL, CSP 仅为 img-src 增加 blob:, 不允许远程任意域名或脚本。视频校验 MP4 容器声明的时长、比例和编码标识; 资源包使用文件 Blob 上传, 不把 2GB 文件转换成 IPC 字节数组。

## 新增作品

作品管理的「新增作品」复用六个编辑分区, 不读取不存在的作品详情。新建时可选择免费、钻石或平台提供的绿宝石定价; 资源包和图片使用新上传的签名回执。上传的 `itemId` 可省略, 当前账号、主窗口和原生文件选择限制保持有效。

主进程根据运行时选项校验分类、版本、定价及回执, 使用独立的 WorkCreateDTO 默认值, 不复用更新 DTO。首版为 `0.1`, 创建不自动提审。参考接口成功响应没有保证返回作品 ID, 因而成功后刷新列表, 由用户打开作品继续编辑, 不通过名称猜测新 ID。新建草稿按账号隔离, 平台拒绝时保留内容, 写入结果不确定时锁定重复创建, 导航后仍保留锁定状态。

2026-10-17 MCP 扩展：`WorkCreateParams.submitReview` 默认为 false，`works_create` 明确传 true 且具有保存和提审授权时，在创建 POST 中发送 `is_check_apply=true`，无需先获得作品 ID。成功按已完成返回，未获得 ID 用 null 表示；后续编辑仍要求准确 ID。现有 UI 的新建确认和创建后补配置流程不变，详见 [ADR-0017](../adr/0017-mcp-create-and-review.md)。

新建与编辑共享表单, 新建模式隐藏分区保存按钮。账号具备 `users/me.prerequisite_switch` 时可新建免费前置模组。PC 同步、关联、授权和折扣可在新建草稿中配置; 创建接口未声明的详情字段保留至创建后, 由用户选定准确作品并确认应用, 详见下文详情扩展说明。
