# 玩家反馈数据接入

玩家反馈页通过宿主会话访问网易接口, 不再读取本地模拟反馈。实现分布在 `packages/contracts/src/rpc/feedback.ts`、`packages/netease/src/endpoints/feedback.ts`、主进程 `ipc/rpc.ts` 和 `plugins/community/src/FeedbackPage.tsx`。

## 能力与协议

| 能力 | 平台协议 | 权限 |
|---|---|---|
| `feedback.list` | GET `/items/feedback/pe/`, `start` / `span` / `type` / `fuzzy_key` | `netease:community.read` |
| `feedback.reply` | PUT `/items/feedback/pe/{id}/reply`, JSON `{content}` | `netease:community.write` |
| `feedback.log` | 无凭据读取网易 CDN 日志地址 | `netease:community.read` |

以上能力只允许应用主界面调用, 未向 MCP 暴露。回复必须携带发起时的账号 ID, 主进程拒绝账号已经切换的写入。会话过期、网络错误和平台业务错误沿用现有错误通道。

协议依据仓库 [接口目录](../reference/netease-api-catalog.md#玩家反馈与开发者反馈) 和参考实现固定版本的 [FeedbackVO 字段定义](https://github.com/BitterLemonn/MCDevManager/blob/d7ecc75dac449addd0782870b85fc25fc1447bee/shared/src/commonMain/kotlin/com/lemon/mcdevmanagermp/data/vo/netease/feedback/FeedbackVO.kt)。仅参考接口行为, 未复制原项目代码。

## 页面行为

- 每页 20 条, 复用玩家评论的共享页码组件, 放在双栏下方；支持上一页、下一页、页码选择和输入跳转, 单页时隐藏。关键词经 350ms 防抖提交平台, 分类使用平台的 `0` 到 `6` 编码。
- 同一页刷新保留现有列表、详情和附件, 后台更新后替换当前页；失败保留该页旧内容, 重试仍请求当前页。翻页期间不显示其他页的记录, 同一查询的总页数保留；返回总数缩减时自动回退到最后有效页。查询与回复筛选结果使用记忆化, 编辑草稿不再重复转换整份列表。
- 页面内相同账号、筛选、分页的并发读取共用一次请求, 完成后立即释放；手动刷新仍获取最新数据, 不以旧缓存代替刷新。
- 回复状态为已回复/未回复时, 按最多 100 条一批读完当前类型和关键词下的全部反馈, 去重后先按回复状态筛选再分页, 总条数与总页数均按筛选结果计算；不发送尚未确认语义的 `reply_count`。状态为全部时继续按服务端页读取。
- 完整查询结果在当前页面状态内保留, 筛选结果翻页或已回复/未回复切换无需重复读取；手动刷新重新读完所有批次后替换。任一批失败或异常空页均报错, 不将部分数据作为完整结果；查询变化后停止后续批次并丢弃旧响应。
- 切换分类、关键词、回复状态或账号回到第一页。翻页重置列表滚动和选中项；草稿按反馈 ID 隔离并跨页保留, 切换账号时清空。
- 回复失败保留草稿, 成功后标记已回复并重新筛选完整结果, 未回复列表自动补齐当前页, 最后一页消失时回退到最后有效页。发送期间禁用发送和编辑, 不自动重试写操作。
- 尊重 `forbid_reply`, 未知分类显示“未知类型”。平台没有提供回复时间, 因此不虚构时间。
- 图片通过现有 `glaze-image` 代理加载。日志仅在打开时读取, 限定 HTTPS 网易 CDN、无凭据、无跳转, 流式限制 1 MiB；暂不支持压缩包、二进制和非 UTF-8 文件。
- 组件冲突内容为结构化 JSON 时提取组件名和说明；无法识别时保留原始文本。

## 真实账号性能采样 (2026-10-15)

用户授权使用当前登录账号测试加载与刷新, 明确禁止发送回复。通过已运行开发版的 `window.glaze.rpc` 调用 `account.current` 和 `feedback.list`, 全程未调用 `feedback.reply`, 不读取或输出 Cookie, 不记录昵称、玩家 ID、反馈正文或附件地址。

计时从渲染进程发起列表 RPC 到完整结果返回, 包含 IPC、主进程会话处理、网易接口请求和数据解析；不含 React 提交、图片下载/解码及应用启动。首轮是已经运行的应用中的第一次本轮采样, 不是冷启动测量。

| 项目 | 样本耗时 (毫秒) | 说明 |
|---|---|---|
| 首屏读取 | 300.1 | 共 638 条, 返回首屏 20 条 |
| 刷新首屏 | 259.4、271.5、211.4、236.3 | 中位数 247.85, 每次真实访问接口 |
| 下一页首次 | 760.9 | start=20, span=20 |

本轮没有发现需要新增结果缓存或预加载的明确瓶颈, 保留已有后台刷新、并发请求合并与列表记忆化。下一页的单次高耗时只能说明本轮存在波动, 当前采样不足以定位到网络或服务端某一阶段, 也不代表长期延迟分布。

## 真实窗口绘制与图片采样 (2026-10-15)

在同一真实账号、前台开发版窗口中, 通过 Computer Use 执行打开反馈页、刷新 3 次、选择带图反馈、打开及关闭图片预览、滚动列表。没有输入或发送回复。

| 操作 | 点击至下一次绘制机会 | RPC 返回至下一次绘制机会 |
|---|---|---|
| 打开反馈页 | 379.2 ms | 10.4 ms |
| 刷新 1 | 392.0 ms | 8.4 ms |
| 含图详情刷新 2 | 358.2 ms | 8.6 ms |
| 含图详情刷新 3 | 316.8 ms | 5.6 ms |
| 选择带图反馈 (不含图片等待) | 7.5 ms | 无需 RPC |
| 打开图片预览 | 7.5 ms | 无需 RPC |

图片为 2560 × 1600。本轮首次创建缩略图后 195.8 ms 触发 load, 再过 9.2 ms `decode()` 就绪；已加载图片的放大预览 load 等待为 0 ms, decode 等待为 0.2 ms。含图详情刷新时没有重建图片元素, 缩略图持续可见。本轮没有清空代理缓存或浏览器缓存, 因此不称为冷缓存测试。

各操作窗口中没有 >50 ms 的主线程长任务, 没有 >33.4 ms 的 rAF 间隔。首图阶段最大帧间隔为 25 ms, 其余打开、刷新、预览和有效滚动样本最大间隔为 4.3–4.6 ms。25 ms 表明存在单次轻微帧波动, 不能表述为完全零掉帧。滚动有效样本为 500 ms；诊断准备阶段有一次没有对应输入的 scroll 标记, 不计入操作结论。

单独开启 Chromium `devtools.timeline` 采样, 覆盖一次滚动及第三次刷新: 4 次 Layout 共 1.583 ms (单次最大 0.702 ms), 58 次 Paint 共 14.744 ms (单次最大 0.375 ms), 9 次 UpdateLayoutTree 共 0.542 ms (最大 0.106 ms)。这些是采样窗口内事件总计, 包含界面其他活动, 不是单次刷新独占耗时；没有采集 GPU 光栅化或显示器实际出光时间。

方法: 临时在反馈列表 RPC Promise 回调起点记录 `glaze.feedback.response`; 被动 MutationObserver 观测列表结束 busy, 双 rAF 估计随后的绘制机会; PerformanceObserver 记录 longtask, rAF 记录帧间隔。双 rAF 是可见更新的近似界限, 不是物理呈现时间；load/decode 等待也不是纯图片解码 CPU 时间。

诊断脚本为 `tools/profile-feedback-ui.mjs` 与 `tools/feedback-ui-probe.js`, 只保留时间、事件计数和图片尺寸等统计, 不保存正文或图片地址。计时标记已从业务 hook 移除, observer 与 trace 均已停止。再次采集 RPC 返回阶段时需要同样的临时计时点；不添加该点时仍可观测点击、DOM、帧与图片事件。

结论: 本轮没有发现持续绘制卡顿或刷新反复加载图片的问题。现有刷新策略及图片复用有效, 未据此增加缓存、预加载或改变产品逻辑。若后续出现多张大图同时展示, 再用同一方法衡量异步解码和缩略图策略的收益。

## 大图首次显示优化

用户随后要求优化首图阶段的轻微帧波动。附件组件显式设置 `decoding="async"`, 在 `decode()` 成功前隐藏图片并显示加载占位, 解码完成后再显示像素；图片仍通过原有代理加载。网络或解码失败显示错误状态, 离开记录后忽略旧图片的异步完成结果。附件 key 包含 URL, 同名图片地址变化时不会沿用旧的就绪/失败状态。

同一张真实 2560 × 1600 附件的本轮对照使用临时代理查询标记, 复用主进程原始字节缓存, 分开渲染器资源实例以观察新解码路径, 没有清空账号数据或全局浏览器缓存。优化后大图 load 等待 6.5 ms、decode 就绪等待 7.3 ms、最大帧间隔 4.3 ms, 无 >50 ms 长任务。优化前同轮最大帧间隔也为 4.3 ms, 没有稳定复现此前的单次 25 ms 波动, 因此不宣称确定的提速百分比；改动保证解码就绪前不参与首次可见绘制。

真实缩略图和放大预览显示正常；9 项反馈测试、全仓类型检查与构建通过。临时代理查询标记和性能 observer 已移除/停止, 没有发送真实回复。提交范围为本会话的反馈接入、刷新优化、图片显示优化与测试诊断工具, 不包含其他模块的并行改动。
