# MCP 接入与作品协作实装

日期：2026-10-16。用户批准按照「AI 接入管理 + 作品协作审批」方案实现。此文描述实际代码，取代 13-mcp.md 中对应的待实现设想；未执行真实网易作品写入验收。

## 使用入口

设置 → AI 接入：开启服务，选择客户端，复制生成的配置并连接，再授予固定的账号范围、默认账号和能力权限。邀请有效期十分钟。初始只读选项不包含收益查询；草稿、上传、保存和提审单独授权。新增账号及界面账号切换不会改变已授权范围。

页面提供真实在线状态、权限调整、素材目录、断开、撤销、待处理请求、AI 草稿、操作结果与最近 500 条调用记录。侧栏显示待处理数量。AI 草稿入口复用作品编辑器，使用独立草稿键；「保存 AI 草稿」只修改本地草稿，原确认请求随修订失效。

平台请求由 `apps/desktop/src/main/mcp/host.ts` 注入。MCP 不构造 Electron IPC 事件，不调用原生选择器专用 IPC。`mcp.*` 管理能力只接受应用主窗口的顶层 frame，外部工具不能批准请求或修改授权。

## 传输与存储

- 正式接入采用 stdio：配置启动应用附带的 `out/main/mcp-bridge.js`，设置 `ELECTRON_RUN_AS_NODE=1`，通过每次启动重新生成的 Windows 命名管道连接主应用。`--mcp` GUI 入口会提示重新复制配置。桥不创建 Chromium 窗口、不读网易会话，也不写主应用状态。
- 必须先打开应用；关闭窗口到托盘后可继续连接，退出应用即断开。不监听 HTTP 或外网端口。
- 每个客户端有随机 256 位凭证，配置只含客户端 ID 和本机路径。桥凭证经 Windows `ProtectedData` 的 CurrentUser DPAPI 加密，通过隐藏的 Windows PowerShell 调用系统加密 API；秘密经标准输入传递，不进入命令行、配置或日志。
- Windows GUI Electron 的 stdin 及多个 Chromium 进程对同一配置目录的加密上下文不适合作为桥。因此桥采用 Node 模式和独立 DPAPI 凭证；主应用的授权、草稿、材料回执、执行记录仍经 Electron safeStorage 加密并原子写入 `userData/mcp/state.bin`，写请求发送前刷盘。
- 管道连接必须验证随机凭证；客户端名称不是认证依据。最多 32 个同时连接、每客户端每分钟 60 次业务调用，同一客户端同时只处理一个工具调用。
- 损坏的授权文件保留原件并停用服务，不以空状态覆盖。未配对客户端只可初始化并读取自己的连接状态资源，不可查询业务数据。

## 工具

只读能力采用契约名将点替换为下划线：账号列表与默认账号、开发者等级、数据概览及日度分析、收益列表/详情/估算、排行榜列表/分页、作品列表/详情/审核反馈、五项活动查询。只暴露带 MCP 元数据、有运行时 Schema、非凭据且非 shellOnly 的能力。

作品编辑入口：

| 工具 | 行为 |
|---|---|
| `works_editor` / `works_options` | 读取编辑文档与实时选项 |
| `works_draft_create` | 创建绑定客户端、账号与作品的隔离草稿；无 itemId 时准备新作品 |
| `works_draft_patch` | 按分区修改明确字段；必须提供当前修订号 |
| `works_draft_validate` / `works_draft_preview` | 业务校验、差异、材料和已授权目录信息 |
| `works_asset_import` | 请求用户选择文件，或从已授权目录按相对路径导入 |
| `works_asset_upload` | 创建固定材料的上传确认请求 |
| `works_create` / `works_save` | 创建/保存确认请求；save 可明确请求保存并提审 |
| `works_submit_review` | 为没有本地修改的现有作品建立提审请求 |
| `works_operation_get` | 查询本客户端操作的准确阶段与结果 |

调用结果同时返回文字 JSON 与结构化 `{ result }`。失败为 `isError: true`，保留错误类别；未知异常不返回本地路径、平台原文或凭据。客户端只能读取自己授权的账号、草稿、操作及材料。

## 材料与草稿

导入与上传分离。目录授权只允许相对路径；拒绝绝对路径、设备/网络路径、备用数据流、父路径及链接/联接点逃逸。文件流式复制为宿主快照，校验源文件在复制期间的稳定性，并记录 SHA-256。上传前重新验证快照哈希和有效期。原生文件选择与上传继续复用现有类型、尺寸、视频格式和资源类别验证。

上传结果不向 AI 返回签名。字段使用 `{ "$asset": "材料ID", "as": "receipt" }`，或 `as: "url" / "name" / "size"`；富文本图片使用 `src="glaze-asset:材料ID"`。引用必须属于同一草稿且已上传。原有媒体只能引用该作品已有值；拒绝新增任意媒体 URL、伪造上传回执和不在分区白名单内的字段。富文本在主进程清理标签与属性。

材料有效期 24 小时，最多 200 个快照，串行导入并限制总空间。启动与每 15 分钟清理过期生成文件；只处理独立快照目录中匹配生成名称的普通文件，保留执行中的材料，不删除用户源文件。草稿修改总量限制 3MB。

## 批准与结果

确认请求绑定客户端、账号、草稿修订、操作序列及材料 ID/哈希，十五分钟过期。外部参数不能免除批准。执行前、业务适配器预检结束及实际发送前重新核对授权、会话与插件状态。保存与提审分别记录阶段，保存后核对批准内容，再调用带内容快照校验的提审适配器；签名回执与平台返回的同一媒体 URL 按相同内容比较。

操作幂等键按客户端和账号隔离，相同请求重试返回同一操作，键与不同内容冲突时报错。重启使待确认请求过期，将执行中请求标记为结果未知。未知结果、已保存但后续失败、平台额外处理等阻止同一作品通过新草稿绕过。用户在应用内核实平台结果后可解除该限制；原请求不可重试，旧草稿仍锁定，应重新读取最新内容建立草稿。

新建成功未返回可靠 ID 时返回 `created_id_unresolved`，不按名称猜测，也不自动提审。创建协议不接受的 PC 同步、关联、授权等配置仍保留在原草稿，用户确认准确作品后建立新草稿并显式应用。

## 验证与限制

- `node tools/test-mcp.mjs`：协议协商、工具 Schema、客户端/账号/草稿隔离、版本审批、冲突、部分成功、未知结果、重试去重、人工核对、材料路径与哈希、Windows 管道认证。
- `node tools/test-mcp-electron.mjs <Playwright 模块 URL>`：隔离临时配置目录，真实 Electron UI、Node 模式 stdio 桥、SDK 客户端、DPAPI、权限拦截、撤销和重启记录。禁用网络，仅使用测试账号。
- `node tools/test-mcp-ui.mjs <Playwright 模块 URL> [浏览器通道]`：真实设置组件的权限、差异、修订绑定确认、窄窗口与截图；使用业务桩。
- 既有作品适配器测试、工作区类型检查及桌面构建继续通过；截图输出在 `node_modules/.cache/mcp-tests/`。

真实网易创建、上传、保存、提审尚未执行端到端验收。平台没有原子版本条件写入协议，最后一次读取与实际提交之间仍存在短暂竞态；字段被平台重新规范化但无法可靠证明等价时会停止提审，要求重新检查。安装包签名/打包后路径及 Electron RunAsNode fuse 需要发行验收。HTTP 接入、第三方插件贡献工具、攻略上传、独立上架、删除作品及申请结算不属于此次开放范围。
