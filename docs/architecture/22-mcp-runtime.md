# MCP 业务直连接入

更新日期：2026-10-17。当前实现按用户要求移除了 AI 草稿工作流与逐次确认。AI 在授权范围内直接查询、编辑和执行业务操作。连接与授权体验按 [ADR-0013](../adr/0013-ai-first-mcp-experience.md) 重新设计，以 AI 为主。

## 本地作品归档

归档记录由主进程 `WorkArchiveService` 按账号保存在应用数据库的 `works.archive.v1:<account>` 设置中，界面和 MCP 共用。应用外壳启动时导入旧 `localStorage` 记录一次，旧记录保留为恢复副本；已迁移账号不会再次导入，防止恢复后的作品被旧窗口重新归档。未同步或记录损坏时阻止相关读取，避免默认暴露旧归档内容。

`works_list`、`works_page`、`works_search` 和 `works_searchReferences` 默认排除归档作品；分页先过滤再计算总数。`works_get`、`works_reviewFeedback`、`works_editor` 以及已有作品的保存、提审、素材和状态操作默认拒绝已归档目标。用户明确要求包含或操作归档作品时，每次调用单独传 `includeArchived: true`；它不会恢复作品，也不会影响后续调用的默认值。操作过程中再次检查归档状态，避免后台读取期间发生归档后继续写入。

`works_archiveState` 仅返回本账号已归档作品 ID；`works_archive`、`works_restore` 使用现有 `works:save` 授权及 `idempotencyKey` 管理本地归档，不改变网易平台状态。变更通过 `works.archiveChanged` 推送给所有窗口，界面立即更新。平台收益、评论等独立业务模块不因作品列表归档改变其原始统计口径。

界面的归档状态由 `WorkArchiveStore` 跨路由共享并合并并发初始化；页面离开后继续接收变更通知，返回列表无需等待重复查询。晚到的读取或失败不会覆盖更新的推送。首次读取失败提供原位重试，未核验记录前不显示作品；显式刷新时保留已核验快照。归档后的分页从同一份列表快照同步计算，缓存到期时后台重新核验；本地归档变更不使平台列表和封面缓存失效。普通列表、归档列表分别记住页码和滚动位置。

## AI 助手页

侧边栏「AI 助手」（`plugins/assistant`，插件 `glaze.assistant`）取代原「设置 → AI 接入」；带 `category: "ai"` 的旧设置链接会跳转到这里。页面内容：

| 区域 | 内容 |
|---|---|
| 开始使用 | 没有连接时显示：三步说明（选工具 → 重启 → 用中文说）、「连接我的 AI 工具」按钮、可复制的示例说法 |
| 等你允许 | 用户关掉弹窗后仍待处理的请求，可在这里拒绝 / 仅这一次 / 一直允许 |
| AI 工具 | 每个工具一张卡片：在线状态、上次使用、三档权限切换、可用账号；「账号与详细权限」打开逐项权限、默认账号和素材文件夹；「移除」作废密钥并删除 Glaze 写入的配置。手动连接标「临时连接」；仅写入配置时显示等待连接，收到真实会话后才显示在线 |
| AI 最近做了什么 | 结果待核实的写操作置顶（核实后点「我已核实」），下方按时间列出工具调用的大白话记录；「清空记录」经弹窗确认后清空所有工具、所有账号的历史记录，保留待核实操作 |
| 设置 → AI 连接服务 | 服务开关、本机端口、不带密钥的手动连接地址，由 AI 助手贡献设置分区 |

全局弹窗 `AccessRequestDialog` 挂在应用外壳上，任何页面都会弹出；应用窗口不在前台时同时发 Windows 通知。关闭弹窗只是隐藏，不等于拒绝。侧边栏底部显示「AI 已连接 · N」，有请求时变为「AI 等你允许 · N」。

## 连接与授权

**一键连接**（推荐）：`mcp.connect { tool, level }` 生成带独立密钥的客户端并写入对应工具配置，服务未开启时自动开启。

| 工具 | 写入位置 | 条目 |
|---|---|---|
| Claude Code | 优先 `claude mcp add --transport http --scope user`；找不到 CLI 时改 `~/.claude.json` | `mcpServers.glaze = { type: "http", url }` |
| Codex | `$CODEX_HOME/config.toml`（默认 `~/.codex`） | `[mcp_servers.glaze] url = ...`，连同 `glaze` 子表一起替换 |
| Cursor | `~/.cursor/mcp.json` | `mcpServers.glaze = { url }` |
| VS Code（Copilot） | `%APPDATA%/Code/User/mcp.json` | `servers.glaze = { type: "http", url }` |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` | `mcpServers.glaze = { serverUrl }` |
| Gemini CLI | `~/.gemini/settings.json` | `mcpServers.glaze = { httpUrl }` |
| 其他 AI 工具 | 不写文件 | 生成「复制给 AI 的一句话」，由 AI 自己配置 |

只改 `glaze` 条目；首次修改前把原文件备份为 `*.glaze-backup`，写入用临时文件加改名；JSON 含注释或格式不标准时不改写，提示用户改用「复制给 AI 的话」。同一工具再次一键连接时，先写入并核对完整连接地址，成功后才撤销旧密钥；失败恢复原配置，保留旧连接与授权。移除连接时只在配置里的地址仍带该密钥时才删除条目。

更换端口先准备新监听并迁移仍有效的一键连接配置，全部验证成功后才停止原监听；任一失败则恢复已改配置、停止候选监听，保留原监听和端口。用户已移除的配置不自动重建；无法读取的配置会阻止迁移并明确提示修复。回滚时若发现配置已被其他程序修改，不覆盖其修改，明确列出需要「重新写入」的客户端。

**连接密钥**：`?key=` 或 `Authorization: Bearer`，24 字节随机值，按常量时间比较，保存在已加密的 `state.bin`，界面快照不返回。密钥对应的客户端在重启、重连后保留授权，多个会话共用同一授权，一个会话断开不影响其他会话。未知密钥返回 401，不会退回配对流程。

**三档权限**（`mcpLevels`，契约在 `@glaze/contracts`）：

| 档位 | 权限 |
|---|---|
| 只看数据 | 业务查询（不含收益）+ 查看应用设置与插件；不含运行日志 |
| 帮我打理（默认） | 全部查询（含收益与日志）+ 回复玩家、消息已读与删除、上传素材、新建与修改作品、打开页面与切换界面当前账号 |
| 完全托管 | 再加上提审、上架 / 撤回 / 调价 / 自测 / 删除、活动报名与轮播图申请、修改应用设置与启停可选插件 |

一键连接默认授权全部已登录账号，默认账号为当前账号。

**AI 主动申请**：已授权客户端的工具列表包含全部工具，未授权的工具描述前注明「首次使用需用户允许」。调用缺权限的工具时先校验参数，再创建请求（同客户端、同权限集合的请求合并，每个客户端最多 5 条待处理，10 分钟过期），调用最多等待 60 秒：

- 一直允许：权限写入客户端授权，调用继续执行。
- 仅这一次：本次调用继续执行；如果调用已超时返回，则留给下一次同类调用使用一次。
- 拒绝：返回 `forbidden`「用户拒绝了…权限」。
- 超时：返回 `permission_pending`，提示 AI 提醒用户去 Glaze 点允许后再试。

保存并提审按一次调用同时检查保存与提审权限，只申请缺少的集合，允许后完整继续。一次性授权预留给单次执行中的调用，成功或异常结束后均失效；并发调用不能重复领取同一次授权。已完成或结果未知的幂等重放只读取旧结果，不重复写入，也不申请或消耗下一次写入的一次性授权；账号和客户端范围检查仍生效。

授权前也可调用两个引导工具：`glaze_status`（是否允许、档位、账号、能做的事、还需申请的权限、下一步提示）和 `glaze_request_access`（`level` / `permissions` + `reason`，把原因展示给用户）。

**手动连接**：不带密钥的地址仍可使用。连接后弹出「允许连接」，允许后获得「帮我打理」权限，只在本次会话有效；新会话不会根据自报名称继承授权。

**内置指令**（MCP prompts）：`daily_report` 今日数据简报、`reply_reviews` 处理差评、`check_works` 检查作品状态、`income_review` 本月收益分析、`feedback_summary` 整理玩家反馈。服务端 `instructions` 要求 AI 用简单中文交流、先调 `glaze_status`、缺权限直接调用让应用弹窗。用户已明确要求且权限已允许的写操作直接执行，无需重复询问，可以简短告知执行内容；删除 / 上架 / 提审 / 回复玩家仍必须符合用户已表达的意图。

无需生成邀请、启动桥进程、创建 AI 草稿或逐次确认保存。原内部快照数据在启动时清理；仅保留仍被上传材料或未解决操作引用的后台快照。

宿主 RPC：`mcp.snapshot`（含 `requests`）、`mcp.installers`、`mcp.connect`、`mcp.answer`、`mcp.grant`、`mcp.revoke`（同时清理配置）、`mcp.directory`、`mcp.setEnabled`、`mcp.resolveOperation`，均为 shellOnly。事件 `mcp.changed` 携带 `pendingCount`、`requestCount`、`connectedCount`。

## 直接修改作品

`works_editor` 读取当前字段；`works_save` 一次调用即可完成指定字段的修改和保存。例如：

```json
{
  "itemId": "4686664860310207622",
  "patch": { "item_name": "MCP测试作品" },
  "base": { "item_name": "旧名称" },
  "idempotencyKey": "rename-unique-request"
}
```

`base` 可选，用于核对 AI 读取时的原值。宿主仍会在实际保存前复核平台数据和作品状态。`patch` 支持现有编辑器全部可写分区字段，包括基本信息、定价、详情、资源、图片、视频、PC 同步、更新与上架设置；只读平台字段不可伪造。普通保存默认不提审；`submitReview: true` 需要提审权限。

`works_create` 接收 `fields` 和可选 `submitReview`（默认 false）。普通新增仅要求保存授权；明确要求新增并提审时设为 true，同时检查保存与提审授权，由同一次创建请求设置 `is_check_apply=true`，不查询 ID 或另发提审请求。平台确认成功后返回 `succeeded`，结果包含 `{ created: true, submittedReview: boolean, itemId: null }`；仅缺少返回 ID 不要求人工核对。后续修改或补配置仍须准确 ID，不按名称猜测；MCP 创建传入 PC 同步、关联、授权证明或折扣等后续配置时在写入前报错，避免静默忽略。旧版 `created_id_unresolved` 记录和未知写入继续要求核实，不随升级自动解除。`works_submit_review` 仍用于按准确 ID 提审已有作品。见 [ADR-0017](../adr/0017-mcp-create-and-review.md)。

`works_upload` 直接导入并上传材料，返回 `assetId`。优先传 `filePath`（运行 Glaze 的电脑上、用户明确指定的素材绝对路径），在已有上传授权内后台完成，不操作窗口；也可用 `directoryId` + `relativePath` 读取已授权目录。三种来源互斥，只有显式传 `interactive: true` 才打开文件选择器；缺少来源、目录参数不完整或来源冲突时直接报错。`promotion_upload` 使用相同来源规则。

```json
{
  "itemId": "4686664860310207622",
  "kind": "image",
  "platform": "pe",
  "channelId": 5,
  "filePath": "D:/宣传素材/组件ICON.png",
  "idempotencyKey": "upload-icon-unique-request"
}
```

直接路径只读取该文件，不枚举目录、不新增持久目录授权。拒绝网络/设备路径、备用数据流、路径跳转、符号链接/联接点、非普通文件和不匹配的格式；复用不可变快照、大小与内容校验、上传前权限复核和幂等记录。上传权限现在包含读取明确指定的本机素材；AI 不得自行扫描或上传无关文件。路径只保留在宿主内部操作数据，不进入工具结果与审计参数。保存字段使用 `{ "$asset": "材料ID", "as": "receipt" }` 或 `url/name/size` 引用；富文本支持 `glaze-asset:材料ID`。材料严格绑定客户端、账号和作品，签名回执始终只在宿主内部使用。新引用还须匹配上传时验证的用途、PE/PC 平台、图片位和资源类别；不匹配时在写入前报错，不能通过改成回执对象或 URL 绕过。视频封面必须来自 videoCover 上传，详情内嵌图片拒绝资源包、视频及失效材料引用。

富文本图片按编辑器格式序列化为 HTML 空元素，不额外注入空 `alt` 或 XML 自闭合标记。2026-10-17 在指定测试作品 `4686664860310207622` 完成后台实测：7 张本地宣传素材上传至 8 个用途（首张轮播图复用于迭代 ICON），保存 6 个图片位、首页推广图和详情长图，回读核对作品保持 `init`。全程未调用文件选择器或操作桌面，未提审、上架或修改其他作品。

## 业务能力范围

| 模块 | MCP 能力 |
|---|---|
| 作品查询 | 列表、分页、名称/ID 搜索、详情、编辑字段、选项、审核反馈、前置与关联搜索 |
| 作品编辑 | 直接保存全部可写字段、新建、上传材料、提审 |
| 作品状态 | 撤回审核、发布、预约/取消上线、提交/取消自测、删除、调价；要求准确 ID 与预期状态 |
| 推广 | 活动、赛道、日期、报名、折扣、轮播图申请查询；报名/取消折扣、上传推广材料、提交/修改轮播图申请 |
| 玩家互动 | 评论与反馈查询、回复、反馈日志读取 |
| 系统消息 | 列表、未读数量、读取并标记已读、全部已读、指定消息删除 |
| 数据收益 | 概览、日度/月度分析、周期/实时收益、结算列表/详情/估算 |
| 首页与应用 | 开发者等级、排行榜/分页/封面、账号基本信息、应用与许可信息 |
| 应用设置 | 一次读取外观、通用、首页榜单与会话偏好；修改外观 / 通用 / 自动登录与过期提醒、设置榜单显示项、恢复排版、清理本地缓存 |
| 插件与日志 | 列出插件、主题与可打开的内置页面；启停可选插件；按级别读取脱敏日志（默认 100、最多 200 条） |
| 页面与账号 | 打开已启用的内置页面并把窗口带到前台；切换界面当前账号，仅限客户端授权且未过期的账号，不改变客户端默认账号 |
| 插件贡献工具 | 从内置清单发现并校验 `contributes.tools`，动态注册 `plugin_<插件短名>_<工具名>`；按插件与客户端权限交集转发主窗口执行，启停刷新列表，复用权限申请、幂等和审计 |

`promotion_upload` 上传推广材料，`promotion_join` 接受 `imageAssetIds` / `videoAssetIds`，`promotion_saveBanner` 接受 `imageAssetId`。宿主把经过归属和用途验证的材料替换为平台回执，禁止客户端伪造签名。

账号登录、Cookie/密码、客户端授权和插件安装仍由应用管理，不提供任意 RPC 转发。`app_general_set` 的开机自启会修改系统登录启动项，工具说明要求先征得用户同意。评论和反馈回复工具只应在用户要求发送回复时调用。实现这些能力不代表自动执行删除、发布或向玩家发送消息。

应用工具权限与参数：

| 权限 | 工具与参数 |
|---|---|
| `app:settings.read` 查看应用设置 | `app_settings_get {}` |
| `app:settings.write` 修改应用设置 | `app_appearance_set { settings }`、`app_general_set { settings }`、`app_session_settings_set { settings }` 均接收完整偏好对象，先读取现值再修改；`app_layout_ranking_set { boards }` 至少保留一个无重复的有效榜单；`app_layout_reset`、`app_cache_clear` 无业务参数 |
| `app:plugins.read` 查看插件 | `app_plugins_list {}` 返回 ID、名称、版本、必需状态、启用状态、错误和内置页面路由 / 标题 |
| `app:plugins.write` 启用或停用插件 | `app_plugins_set_enabled { id, enabled }`，沿用注册表对必需插件、当前主题和损坏插件的拒绝规则 |
| `app:logs.read` 查看运行日志 | `app_logs_list { level?, limit? }`，级别默认 `all`，条数默认 100、上限 200，返回 `entries` 与 `truncated`；宿主脱敏后再通过 `publicValue` |
| `app:navigate` 打开页面与切换当前账号 | `app_open_page { route, params? }`、`app_switch_account { account }`，账号必须显式指定 |

所有写工具（含导航与切换）都必须提供 `idempotencyKey`；所有对象拒绝未知字段。应用设置不依赖默认账号是否有效，审计账号为空，幂等键也不随默认账号变化。切换账号在异步会话验证后、实际选择前再次复核授权。IPC 与 MCP 共用应用操作函数和服务，分别广播 `appearance.changed`、`general.changed`、`sessionSettings.changed`、`layout.rankingChanged`；插件、缓存和账号沿用服务自身的广播回调。

导航只接受构建时内置清单声明且非 `chrome: "none"` 的页面，并检查所属插件已启用；没有主窗口时明确失败。主进程发送 `app.navigate`，AppShell 通过现有 `navigation.navigate` 打开页面。当前作品详情依赖 WorksPage 内部状态，没有作品 ID 路由参数，因此 `params` 只接受空对象，不伪造详情深链接。内置插件贡献工具已接入，具体清单、参数、权限与执行规则见 [插件贡献工具](13-mcp.md#插件贡献工具)；第三方代码插件安装仍未开放。

## 执行与可靠性

- 工具拥有显式参数 Schema，拒绝未知字段。绑定授权账号，不跟随界面账号切换。每次执行前及实际发出平台请求前复核账号、权限与插件状态。
- 写请求提供 `idempotencyKey`；按客户端、账号和方法隔离。相同请求复用结果，不重复发送；相同键换内容时报错。
- 最近操作保留 5000 条终态记录及全部执行中、未核实记录；更早终态自动移入同一加密状态文件的 `operationArchive`，不再因累计次数封顶。归档结果与幂等键持续保留，可跨重启查询和去重，磁盘用量随历史增长；归档不会解除未知结果或部分成功写入的保护。
- 后台操作状态先加密刷盘再写入平台，返回结构化结果和操作 ID。失败或结果未知带 `isError`；`unknown` 禁止自动重试，须核对平台结果。
- 同一作品写入串行；其他业务按账号和模块串行。已有未解决写入结果时阻止继续覆盖。
- 不再对外提供 `works_draft_*`、`works_asset_*`、`mcp.editDraft` 和 `mcp.decide`。内部快照执行器保留以复用材料校验、版本比较与失败恢复；完成的无材料快照立即清理。
- 本机只监听 `127.0.0.1`，校验 Host/Origin；最多 32 个会话，空闲 30 分钟释放会话，输入最多 3MB，每客户端每分钟最多 60 次业务调用。
- 参数校验在权限申请之前，格式错误的调用不会打扰用户。
- 活动及轮播图申请记录查询省略 `page` 时默认第一页（0），显式分页及参数边界保持不变。

### 配置自检与官方 CLI 优先

- Claude Code 一键连接优先调用官方 CLI：依次查找 PATH、`~/.local/bin/claude.exe`、Claude 桌面端自带的 `%APPDATA%/Claude/claude-code/<版本>/<构建>/claude.exe`（含 MSIX 包目录），找不到才直接改 `~/.claude.json`。
- `mcp.snapshot` 会核对每个一键连接工具的完整连接地址（含端口和密钥），无法读取也视为需要修复；被其他程序或手动操作删掉、改地址时，卡片提示「连接配置被移除或覆盖」，并提供「重新写入」（`mcp.repair`，用原密钥重写，不发新密钥）。不会自动重写，避免违背用户在 AI 工具里主动删除的意图。
