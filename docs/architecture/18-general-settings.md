# 通用设置实装

## 行为

| 设置 | 已接入的行为 |
|---|---|
| 开机自启 | 使用 Electron 的 Windows 启动项接口，读回实际启用状态；系统禁用会反映到开关和提示中 |
| 启动后打开 | 有有效本地登录会话时选择首页、作品管理或上次页面；无会话、已过期仍进入对应登录页 |
| 上次页面 | 自动记录已登录用户访问的安全页面入口；不保存作品 ID、查询参数、登录流程或编辑草稿 |
| 关闭窗口 | 托盘模式隐藏并保留进程，点击图标或“显示窗口”恢复；菜单“退出应用”和退出模式真正结束进程 |
| 账号管理 | 未登录也能进入账号管理页并添加账号或操作保存的账号列表 |
| 清除缓存 | 清理 Electron HTTP 资源缓存、代码缓存、图片代理内存及作品/分析查询缓存；部分失败分别提示 |

- 主进程 SQLite `settings` 表保存 `general`、`lastRoute`，复用已有迁移，无新增表。
- 设置经主进程校验并保存成功后才更新控件。写入期间禁用控件；失败时回读实际状态。
- 原生自启更改后会读回校验；数据库保存失败时恢复原生启动状态，并报告恢复失败。修改其他选项不重写启动项。
- Windows 开机自启使用独立名称 `GlazeMCDevManager`，开发版使用 `GlazeMCDevManager.Dev` 和带引号的项目路径参数。其他系统禁用该开关，仍可使用其他通用设置。
- 只读查询 Windows 状态，不会在每次启动时自动覆盖用户在系统设置中的选择。
- 单实例锁让重复启动恢复已有窗口，避免托盘隐藏后再启动多个进程。
- 托盘创建失败时不隐藏窗口；退出遇到页面未保存内容时提供留在页面或放弃的选择，取消后恢复正常托盘行为。
- 设置页及账号管理页允许未登录访问；业务页面仍保留登录保护。

## 缓存清理边界

通过 Electron 的 `clearCache()`、`clearCodeCaches({})` 清理资源，不递归删除用户目录，不调用 `clearStorageData()`，不清除 Cookie、数据库、加密凭据、偏好或磁盘文件。

图片代理清理会增加代数，清理前的在途下载不会重新填充缓存。`cache.cleared` 事件失效作品和分析缓存并取消已排队的作品预加载；保留当前编辑器的表单状态，不强制刷新窗口。

## 接口

- `general.get` / `general.set`：通用配置与 Windows 自启状态。
- `general.clearCache`：返回资源缓存释放字节估计和部分失败列表；并发请求共享一次清理。
- `app.rememberRoute`：仅保存允许的页面入口。
- `general.changed` / `cache.cleared`：同步已挂载界面和内存缓存。
- 新接口限制主应用窗口的主框架调用，不对 MCP 暴露。
