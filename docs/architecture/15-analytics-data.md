# 数据分析真实数据接入

数据分析插件通过现有主进程会话通道读取当前账号的普通手游资源数据。请求不在渲染进程携带 Cookie。当前范围与作品列表一致, 不含端游或联机大厅内购商品。

资源选择与上游 `GetResourceListUseCase(onlineOnly = true, excludePrerequisites = true)` 对齐: 读取列表的 `online_time`, 排除从未上架和前置模组, 保留曾上架但当前下架/审核中的作品。不能仅按当前 `status` 判断是否有历史数据。

## 接口与统计口径

| RPC | 平台接口 | 用途 |
| --- | --- | --- |
| `works.list` | `/items/categories/pe/` | 真实资源选择列表 |
| `analytics.daily` | `/data_analysis/day_detail/` | 数据追踪、模组分析及平台同类均值 |
| `analytics.monthly` | `/data_analysis/month_detail/` | 原生月汇总, 保留历史资源 |
| `analytics.realtime` | `/items/categories/pe/{id}/incomes/` | 各资源当日总额、订单明细 |

字段依据仓库的 [接口清单](../reference/netease-api-catalog.md) 及其固定版本上游模型核对:

- [日/月模型 AnalyzeVO.kt](https://github.com/BitterLemonn/MCDevManager/blob/d7ecc75dac449addd0782870b85fc25fc1447bee/shared/src/commonMain/kotlin/com/lemon/mcdevmanagermp/data/vo/netease/analyze/AnalyzeVO.kt)
- [实时订单模型 ApplyIncomeDTO.kt](https://github.com/BitterLemonn/MCDevManager/blob/d7ecc75dac449addd0782870b85fc25fc1447bee/shared/src/commonMain/kotlin/com/lemon/mcdevmanagermp/data/dto/netease/income/ApplyIncomeDTO.kt)

日期按北京时间计算。日追踪截至昨天; 月汇总包含当前未完结月份; 实时查询将北京时间 00:00–23:59:59.999 转为 UTC 参数。

缺少日期或指标时显示 `—`, 图表留空, 不补零。日均按实际有值的日期计算。评分为平台日评分的算术均值, 不伪造加权样本。月汇总未提供购买次数合计, 因而只显示钻石、绿宝石与下载量。

模组对比使用平台的 `avg_first_type_buy`、`avg_first_type_diamond`、`avg_first_type_focus`; 不生成同类评分。比较分母为零时显示 `—`。

实时汇总使用 `total_diamonds`、`total_points`、`count`, 不用订单明细推算总额。订单显示 `price`/`price_type` 标价和原始退款状态, 不把所有订单标为已完成。玩家标识 `app_uid` 不传给渲染层。

## 请求行为

日数据每批最多 20 个资源, 同时最多 3 批请求; 实时请求最多并行 4 个资源, 任意请求完成即填补空位。入口验证日期、时间跨度和资源 ID。实时部分失败时标明失败资源, 汇总仅计入成功部分; 登录过期停止调度后续请求并返回错误。日查询任一批失败时停止后续调度且不显示部分合计。

页签首次访问时挂载, 后续切换保留数据和筛选; 实时收益在重新进入时自动更新。刷新重查资源列表和当前分析。账号改变时重建页面状态, 避免迟到响应污染新账号。

## 月汇总解析失败修正

用户反馈月汇总从加载转为通用格式错误。复核上游 `MonthTrendChart`、`MonthDetailUseCase`、`AnalyzeVO` 和 `ApiFactory` 后修正:

- 月汇总不再因同一资源/月份有多条记录而整页失败。保留记录, 由已有聚合逻辑按资源与月份求和, 与上游按月份汇总所有行的方式一致; 日数据重复检测不变。
- 月份解析支持有效的紧凑/带连字符月份及完整日历日期, 归一化成 `YYYY-MM`; 无效月份和日期仍拒绝, 不截取无效日期伪造月份。
- 月汇总请求排序对齐上游的 `DESC`, 读取超时单独设为 60 秒, 与上游客户端读取上限一致; 其他调用维持原有 15 秒。
- HTTP 客户端将响应体读取与 JSON 解析分开, 读取超时/断流不再误报格式错误。非 JSON 的 HTTP 错误保留状态码, 不显示原始响应正文。字段校验失败会提示接口类别、行号和字段名, 不显示账号凭据或原始业务数据。

新增月份形式、重复月记录聚合、错误字段提示、响应体超时/断流和 HTML 网关错误测试。22 项分析测试、34 项作品/HTTP 回归测试通过。未取得该账号的原始响应, 因而不能断言截图具体由重复记录、日期格式或传输错误中的哪一项触发; 线上恢复仍需重启后实际查询确认。

## 月汇总载荷兼容与结构诊断

后续截图明确报错为“月汇总的 data 字段不是记录数组”。再次核对参考项目 `AnalyzeApi`、`ResponseData`、`AnalyzeVO` 和 `MonthDetailUseCase`, 其声明仍为外层响应 `data` 内嵌 `{ data: 记录数组 }`, 没有找到可证实该账号实际响应结构的样本。

月汇总适配器现在同时接受 HTTP 层解包后的直接记录数组及原有 `{ data: 记录数组 }`。直接数组兼容属于防御性修正, 不是对截图根因的确认; 不递归搜索未知字段、不把 null 或异常对象当空数组。解析错误追加载荷、data、data.data 的类型和数组长度, 不包含原始值或任意字段名, 便于下一次实际查询定位结构差异。日追踪的载荷约定不变。

新增端到端模拟 HTTP 响应的直接/嵌套数组、空数组、范围过滤、异常结构诊断及字段校验测试, 分析回归测试共 24 项通过。仍需重新启动应用后查询, 确认该账号是否恢复; 若未恢复, 新提示可提供缺失的结构证据。

后续截图确认载荷是缺少 `data` 字段的对象, 排除了直接数组的兼容分支, 但仍没有给出对象的字段。增加有界的月记录集合识别: 在最多两层对象包装、64 个容器内, 只寻找包含 `iid`、`monthid` 与月指标字段的数组; 必须只有一个候选集合, 并将全部行交给现有字段校验。日记录、未知空数组、多个候选、过深/过大的包装均不转成成功结果。原有明确 `data` 数组与直接数组约定保留。

失败诊断增加最多两层、每层 8 个字段的结构说明, 仅输出类型和数组长度, 隐去标识类与凭据类键, 不输出业务值。新增包装识别、日记录排除、歧义拒绝、坏行保留校验和诊断脱敏测试; 26 项分析测试、相关文件 Biome 检查及构建通过。此次类型检查报告另一个在改动的收益模块 `income.ts` 第 112、119 行的泛型参数错误, 未修改该模块。尚未验证真实账号的月汇总恢复, 不将兼容测试表述为线上成功。
