# 项目目标与决策记录

这份文档是项目的**唯一事实来源**：做什么、不做什么、已经敲定了什么、现在做到哪一步。每次新对话先读这里；方案有变化时先改这里，再改代码。

- 架构细节见 [docs/architecture](architecture/README.md)，重大技术决策的理由见 [docs/adr](adr/README.md)。
- 本文只记结论和链接，不展开细节。

## 1. 项目目标

**GlazeMCDevManager**（显示名 Glaze MC Dev Manager，曾用名 GlazeMCDevStudio）是给网易我的世界开发者用的 Windows 桌面管理工具。

1. **覆盖开发者日常管理业务**：多账号登录与切换、首页概览、作品管理、数据分析、玩家反馈、玩家评论、消息。业务范围参考 [MCDevManager](https://github.com/BitterLemonn/MCDevManager)。
2. **账号管理优先**：第一个落地的业务模块是账号（登录、过期重登、多账号切换、账号管理页）。
3. **模块化**：每个业务模块都是独立插件，内置功能和第三方插件用同一套插件 API。
4. **排版自由**：页面由组件拼成，用户可以拖拽、缩放、增删，并能恢复默认布局。
5. **主题可多套扩展**：新增主题只需要一个主题包，不改组件代码。
6. **开放插件**：允许其他用户开发主题和功能插件，在受控权限内运行。
7. **凭据安全**：Cookie 和密码只存在主进程并加密落盘，插件和界面永远拿不到。
8. **数据正确**：查询失败要明确显示，不能显示成零或空。
9. **AI 工具可接入**：设计每个功能时都要考虑让外部 AI 工具（Claude Code、Codex、Cursor 等）通过 MCP 使用。做法是每个功能先定义为能力，界面、插件、MCP 都调用同一份能力。见 [13 能力层与 MCP 接入](architecture/13-mcp.md)。

## 7. 本文档的维护规则

出现下面任一情况，**在同一次改动里**更新本文档：

- 用户敲定了新方案，或推翻了旧方案 → 在第 3 节追加一条；涉及架构的同时补 ADR 并改对应架构文档。
- 范围变化 → 改第 1、2 节。
- 完成或开始一个任务 → 改第 5 节的状态和"下一步"。
- 待定事项有了结论 → 从第 4 节移到第 3 节。
