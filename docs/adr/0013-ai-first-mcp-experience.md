# ADR-0013 AI 助手：一键连接、连接密钥与 AI 主动申请权限

- 状态：已接受
- 日期：2026-10-16
- 关联：调整 ADR-0008 的配对方式；实施细节见 [22 MCP 实装](../architecture/22-mcp-runtime.md)

## 背景

旧的接入方式对不懂技术的用户很不友好：要自己打开服务、理解端口、复制地址并手改 AI 工具的配置文件；每次 AI 工具重启都会被当成新客户端，需要在 10 分钟内回到设置页重新勾选账号和 15 项权限；授权前 AI 一个工具都看不到，没法引导用户；权限请求只能在设置页处理。用户要求在照顾体验的前提下重新设计，并以 AI 为主。

## 决定

1. **独立入口**：侧边栏新增「AI 助手」页（`glaze.assistant` 插件），设置页不再有 AI 接入分类，旧链接跳转到新页面。
2. **一键连接**：应用检测本机的 Claude Code、Codex、Cursor、VS Code、Windsurf、Gemini CLI，替用户写入配置（Claude Code 优先走官方 CLI；JSON/TOML 只替换 `glaze` 条目，首次修改前备份原文件，带注释的文件不改写）。检测不到的工具生成一句「复制给 AI 的话」，让 AI 自己完成配置。
3. **连接密钥**：每次一键连接生成独立密钥写进连接地址（`?key=`，也接受 `Authorization: Bearer`）。服务端按密钥认人，AI 工具重启不需要重新授权；未知密钥直接拒绝（401），不退回配对流程。移除连接时密钥立即作废，并尽量删除 Glaze 写入的配置。改端口时自动重写已连接工具的配置。
4. **三档权限**：只看数据 / 帮我打理 / 完全托管，一键连接默认「帮我打理」（用户选择）；逐项权限收进「账号与详细权限」。
5. **AI 主动申请**：已连接的工具能看到全部工具，未授权的工具描述里注明首次使用需允许。缺权限时，应用在任何页面弹出请求（同时发系统通知），用户可以选择一直允许、仅这一次或拒绝；工具调用最多等待 60 秒，允许后自动继续执行。授权前也提供 `glaze_status` 和 `glaze_request_access`，供 AI 引导用户。
6. **手动连接**：不带密钥的连接仍然可用，但会弹窗请求「允许连接」，允许后获得「帮我打理」权限，只在本次会话有效。
7. **内置指令**：通过 MCP prompts 提供今日数据简报、处理差评、检查作品状态、本月收益分析、整理玩家反馈。
8. 已授权的写操作**保持直接执行**，不增加逐次确认（用户选择，沿用既有决定）。

## 后果

- 小白用户的接入流程缩短为「选工具 → 重启 → 用中文说」，权限按需出现。
- 应用会写入其他程序的配置文件，因此只在用户点击后写入，只改自己的条目，并在首次修改前备份。
- 密钥保存在已加密的 MCP 状态文件中，连接地址本身就是凭据，界面提示不要外发；服务仍只监听 127.0.0.1。
- 每个工具最多同时有 5 条待处理请求；关闭弹窗不等于拒绝，请求会留在「AI 助手」页直到过期（10 分钟）。
- 「仅这一次」在调用已经超时返回后才被点下时，会留给 AI 的下一次同类调用使用一次。
