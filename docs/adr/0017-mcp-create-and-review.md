# ADR-0017 MCP 新增作品与新增并提审直接完成

- 状态：已接受
- 日期：2026-10-17
- 关联：补充 ADR-0012 的创建结果语义，沿用 ADR-0013 的授权后直接执行

## 背景

过去 MCP 创建成功后统一返回 `created_id_unresolved`，需要用户核对新作品才能继续。参考项目在已核实的 d7ecc75 提交中，通过创建接口的 `is_check_apply` 区分仅创建和创建并提审，响应按不返回业务数据处理，成功后返回列表；这个流程无需先取得 ID 再单独提审。只参考接口行为，独立实现，不复制参考项目代码。

## 决定

- `works_create` 增加可选 `submitReview`，默认 false。仅用户明确要求新增并提审时传 true，以同一次创建 POST 的 `is_check_apply=true` 执行，不另发提审请求。
- 普通新增要求 `works:save`；新增并提审要求保存与提审两项授权。沿用一次申请全部缺少权限、一次授权仅供一次调用、发送前重新核验的规则。
- 平台明确确认成功后返回 `succeeded`。结果包含 `created`、`submittedReview` 和 `itemId`；当前未取得可靠 ID 时为 null，单纯完成创建不要求人工核对，也不按名称猜 ID。
- 创建后继续修改或应用 PC 同步、关联、授权证明和折扣配置仍须准确 ID。MCP 创建遇到这些待后续应用的配置时在写入前明确报错，避免静默丢弃；现有 UI 的创建后选定作品并应用配置流程保持不变。
- 结果未知时保留锁定和人工核实，相同幂等请求只读取原结果。旧版 `created_id_unresolved` 操作继续保留，不在升级时擅自认定完成。

## 后果

已授权且参数有效的普通新增、新增并提审可直接后台完成，不因无返回 ID 增加人工步骤。网络失败、缺授权以及创建后编辑仍有明确边界。协议和服务使用离线桩验证，不用真实作品做自动创建或提审试验。
