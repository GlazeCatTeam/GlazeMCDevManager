# ADR-0009 登录使用网易官方登录窗口

- 状态：已接受
- 日期：2026-10-15

## 背景

原项目的邮箱登录复刻了网易未公开的四步协议：SM4 加密参数、RSA 加密密码、本地 VDF 计算。这样做要逆向并维护网易的加密常量，网易一改协议就失效；触发人机验证、手机验证时也无法处理；应用还要经手并保存用户密码。

## 决定

- 邮箱登录改为打开网易我的世界开发者平台自己的登录页（`https://mcdev.webapp.163.com/#/login/`）。窗口使用一次性的内存会话分区，只允许加载网易域名，拒绝所有权限请求，不注入 preload。
- 用户在网易页面里完成登录（验证码、手机验证都由网易处理）。主进程监听这个分区的 Cookie，拿到 `NTES_SESS` 后读取 `P_INFO` 里的通行证账号，关闭窗口并清空分区，再用 `GET /users/me` 验证会话。
- 保留 Cookie 导入：粘贴完整 Cookie 或 `NTES_SESS` 的值，验证通过才保存。
- 应用不再有密码输入框和「记住密码」，不保存任何密码。

## 后果

- 不需要复刻加密协议，网易登录页改版时只要登录后仍下发 `NTES_SESS` 就不受影响。
- 应用从结构上碰不到密码，凭据只剩会话 Cookie，按 ADR-0006 加密保存在主进程。
- 登录体验是网易的页面，不是应用自己的表单；会话过期后要重新在网易窗口登录，无法用保存的密码自动重登。
- 网易接口不返回开发者 UID，账号改用本地 ID，按通行证账号去重（见 [07 会话与网易接入](../architecture/07-session-and-netease.md)）。
